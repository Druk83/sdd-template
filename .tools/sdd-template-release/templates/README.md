# SDD Framework

> **Версия:** `{{VERSION}}`

`package_id`: `sdd-template`.

Это переносимый релиз SDD Framework для проекта-потребителя. Релиз устанавливается
только в `.agents/{{RELEASE_DIR}}/` и не заменяет корневые инструкции проекта.
Установщик создаёт или дополняет корневой `AGENTS.md` коротким управляемым
разделом для использования документации Framework; весь пользовательский текст
вне этого раздела сохраняется. Инструменты сопровождения исходного репозитория
и инструкции выпуска в проект-потребитель не устанавливаются.

Сокращённые пути каталогов фреймворка внутри его документации относятся к
каталогу `.agents/{{RELEASE_DIR}}/`. Результаты документирования создаются в
корне проекта-потребителя.

## Точка входа

Правила использования документации находятся в `sdd-template.instructions.md`.
При явной команде установки или обновления агент получает актуальную процедуру
из исходного репозитория `Druk83/sdd-template`; процедура и инструменты обновления
не входят в установленный пакет.

Короткие команды после подключения Framework:

```text
инициализируй сдд
обнови сдд
вернись на версию X.Y.Z
```

Они относятся только к `SDD Framework` с `package_id: sdd-template` и источником
`Druk83/sdd-template.git`.

## Состав

- `.manifest/` — манифесты и правила фреймворка;
- `.requirements/` — шаблоны документации;
- `.approach/` — подходы и реестр подходов;
- `.diagrams/` — эталонные исходники диаграмм Framework;
- `.chatlog/` — каталог журналов самого Framework, создаваемых только по запросу;
- `.project-structure.json` — структура проекта-потребителя;
- `.tools/` — переносимые инструменты;
- `release-registry.json` — перечень доступных релизов и их источников;
- `.gitignore` — правила исключения runtime и локальных файлов пакета;
- `release-manifest.json` — машинные сведения о составе и происхождении релиза.

## Источник

Единственный источник релизов: `Druk83/sdd-template.git`. По умолчанию используется
ветка `main`; конкретная версия выбирается по записи в `release-registry.json`.

Другие каталоги `.agents/` проекта-потребителя и пользовательский текст
`AGENTS.md` вне управляемого раздела не являются частью пакета и не должны
изменяться при установке. Коллизии правил возвращаются установщиком для решения
пользователем.

Рабочие каталоги проекта `.source/`, `.tasks/` и `.issues/` создаются отдельно
в корне проекта по стандартному каркасу установщика. Корневой `.chatlog/` для
Framework не создаётся.
