# Правила SDD Framework для проекта

Эти правила относятся к работе с технической документацией проекта.

## Корень Framework

Определи `FRAMEWORK_ROOT` по полю `framework.release_dir` корневого
`.project-structure.json`. Перед использованием проверь
`FRAMEWORK_ROOT/release-manifest.json` и SHA-256 файлов установленного релиза.
Пути к манифестам, шаблонам, подходам и инструментам Framework вычисляй от
`FRAMEWORK_ROOT`. Документы проекта создавай в корневых каталогах проекта,
указанных ниже.

## Документация проекта

- `FRAMEWORK_ROOT/.requirements/` — read-only шаблоны и методики.
- `docs/requirements/` — итоговые требования, которые создаёт разработчик.
- `.tasks/` — текущие задачи и планирование.
- `.issues/` — проблемы и дефекты проекта.
- `FRAMEWORK_ROOT/.manifest/` — правила работы с соответствующей областью.
- `README.md` — обзор проекта.

Соблюдай выбранный манифест и правила иерархии из
`FRAMEWORK_ROOT/.manifest/hierarchymanifest.md`. Не перезаписывай пользовательские
документы и не создавай ссылки или пути Framework с жёстко заданным номером
версии.

## Размещение результатов

| Шаблон | Результат |
|---|---|
| `FRAMEWORK_ROOT/.requirements/предметная область.md` | `docs/requirements/предметная область.md` |
| `FRAMEWORK_ROOT/.requirements/требования/*.md` | `docs/requirements/требования/<имя-документа>.md` |
| `FRAMEWORK_ROOT/.requirements/домены/*.md` | `docs/requirements/домены/<имя-документа>.md` |
| `FRAMEWORK_ROOT/.requirements/сценарии/*.md` | `docs/requirements/сценарии/<domain>/<имя-документа>.md` |

Путь и расширение результата обязательны. Выбирай точное имя по соглашению
проекта, затем по процедуре Framework; не переименовывай существующий результат
только ради шаблона. `.gitkeep` добавляй только в пустой каталог, который нужно
сохранить в Git.
