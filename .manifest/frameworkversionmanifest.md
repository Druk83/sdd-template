# Framework Source Version Manifest (H2)

Политики и обязательные стандарты определения и изменения общей версии
исходного набора SDD Framework. Этот манифест source-only и не задаёт правила
версии проекта-потребителя.

**Аудитория:** только мета-репозиторий SDD Framework; **Экспорт:** исключён

Манифесты Framework не имеют независимых номеров версий: они входят в общий набор
и получают его версию. Изменение манифеста оценивается как изменение набора по
правилам SemVer ниже.

---

## frameworkversion.H3.1 Храни текущую версию в корневом README

Единственный источник текущей версии набора шаблонов — поле `Версия` в корневом
`/README.md`. `release-registry.json` индексирует доступные релизы и не заменяет
этот источник.

## frameworkversion.H4.1 Меняй общую версию набора

- Все шаблоны и манифесты Framework используют версию общего набора.
- Не назначай отдельную версию одному манифесту или шаблону.
- При изменении любого шаблона оцени изменение общего набора и обнови его версию
  по SemVer.

## frameworkversion.H3.2 Применяй SemVer к набору Framework

Версия набора следует Semantic Versioning.

## frameworkversion.H4.2 Выбирай уровень SemVer по изменению

| Тип версии | Когда использовать |
|------------|-------------------|
| MAJOR (X.0.0) | Несовместимые изменения структуры или контрактов |
| MINOR (0.X.0) | Новые обратно совместимые возможности |
| PATCH (0.0.X) | Исправления и уточнения без несовместимости |

## frameworkversion.H3.3 Синхронизируй записи об изменении набора

Изменения версии и даты набора отражай в корневом `/README.md`, CHANGELOG и
внутреннем реестре `.requirements/трек разработки.md`, если эти записи ведутся.
Проверяй совместимость существующих потребительских документов с изменениями.

## frameworkversion.H4.3 Обновляй записи при изменении шаблонов

При подготовке изменения Framework:

1. Обнови версию в корневом `/README.md`.
2. Обнови дату в реестре шаблонов (`.requirements/трек разработки.md`, раздел 9).
3. Добавь запись в CHANGELOG, если он ведётся.
4. Проверь совместимость существующих потребительских документов с изменениями.

Не изменяй `.requirements/**` без оценки и обновления версии набора. Используй
одну версию набора для всех шаблонов и манифестов. Правила commit, tag, release
registry и публикации описаны в `.manifest/gitmanifest.md` и документации
`.tools/sdd-template-release/`.
