# Chat Log Manifest (H2)

Политики и обязательные стандарты записи и ведения логов сессий чата агента с разработчиком.

**Аудитория:** проект-потребитель SDD Framework; **Экспорт:** включён

---

## chatlog.H3.1 Сохраняй логи только по явному запросу разработчика
Запись логов не выполняется автоматически. Инструмент активируется командой разработчика.
**Триггеры запроса:**
- "сохрани логи", "запиши логи", "обнови логи чата", "сделай чатлог"
- Любая формулировка с явным указанием сохранить историю сессии

Сам запрос на создание, сохранение или обновление чатлога не является содержанием
сессии для записи: не включай в лог это сообщение разработчика и ответ агента,
который только подтверждает или описывает выполнение записи. Если в том же
сообщении разработчик также поставил отдельную задачу или сообщил факты по
проекту, сохрани эту содержательную часть без инструкции о записи чатлога.

---

## chatlog.H4.1 Определи целевой файл лога
Перед записью определи файл назначения. Для установленного SDD Framework
каталог `.chatlog/` означает каталог внутри `FRAMEWORK_ROOT`, то есть
`.agents/sdd-template-X.Y.Z/.chatlog/`. Корневой `.chatlog/` проекта для
журналов Framework не создаётся.
**Правило именования:**
- Файл по умолчанию: `FRAMEWORK_ROOT/.chatlog/session.md`
- Если разработчик указал имя явно — использовать его
- Расширение всегда `.md`

---

## chatlog.H3.2 Не дублируй уже записанные обмены
При повторном запросе в той же сессии дополняй файл, а не перезаписывай.
**Почему важно:**
Разработчик может запрашивать сохранение несколько раз за сессию — ранее записанное не должно теряться.

---

## chatlog.H4.2 Используй маркер последней записи
При обычном повторном сохранении используй маркер в конце файла как границу
между уже записанными и новыми обменами. Явный запрос подробно оформить ранее
сохранённую историю является отдельным действием: обнови существующие записи на
месте, не добавляй вторую реконструкцию тех же обменов.
**Формат маркера:**
```
<!-- last-saved: YYYY-MM-DDTHH:MM -->
```
**Обычное продолжение:**
1. Прочитать целевой файл.
2. Найти строку `<!-- last-saved: ... -->` — это граница последней записи.
3. Дописать только обмены, произошедшие после маркера.
4. Обновить маркер датой текущей записи.
5. Если файл пуст или не существует — записать всю историю сессии и добавить маркер.

**Явная ретроспективная детализация:**
1. Сверить существующие записи с доступной историей этой сессии.
2. Переписать соответствующие блоки обменов на месте, сохраняя хронологию и
   фактическое содержание сообщений.
3. Не дублировать сохранённый обмен в новом формате и не дополнять историю
   сведениями, которых нет в доступном контексте.
4. Сохранить один маркер в конце файла и обновить его после изменения.

## chatlog.H4.3 Соблюдай формат записи обмена
Каждый обмен записывается в строгом формате.
**Формат:**
```markdown
Разработчик:
<текст сообщения разработчика>

---

Агент:
<текст ответа агента>

---
```
**Правила:**
- Разделитель `---` после каждого блока разработчика и агента
- Не включать служебные метаданные IDE (открытые вкладки, путь активного файла)
- Не включать вложения и изображения — только текстовый контент
- Ответ агента записывается кратко: суть действий и результат, без повтора всего тела ответа

---

## chatlog.H3.3 Не записывай чувствительные данные
Логи сессий могут попасть в репозиторий.
**Запрещено записывать:**
- API-ключи, токены, пароли из сообщений
- Пути с именами пользователей машины (заменяй на `<user>`)
- Содержимое `.env` файлов

---

## chatlog.H4.4 Структура директории `.chatlog/` Framework
```
FRAMEWORK_ROOT/.chatlog/
  session.md        <- основной файл лога текущей сессии
  <name>.md         <- дополнительные файлы если разработчик указал имя
```
**Файл `FRAMEWORK_ROOT/.chatlog/session.md` перезаписывается при старте новой
сессии** только если разработчик явно попросит создать новый лог. Иначе
дополняется.
