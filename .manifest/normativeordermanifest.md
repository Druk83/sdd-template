# Normative Order Manifest (H2)

Правила распознавания нормативного порядка событий и построения текстовой формулы с диаграммой графа-автомата.

---

## normativeorder.H3.1 Строй формулу и диаграмму из одной модели переходов
Формула и диаграмма обязаны получать данные из одной канонической модели ориентированного графа. Формула показывает основной нормативный маршрут, а исключающие ветви выводятся отдельно; DOT показывает обе части модели.
**Почему важно:** единый источник исключает появление неподтверждённых переходов при независимой обработке текста и изображения.

---

## normativeorder.H4.1 Сохраняй модель с уникальными узлами и переходами
Сформируй `NormativeOrderModel` из фактической последовательности.

```ts
interface NormativeOrderModel {
  nodes: string[];
  transitions: Array<{ from: string; to: string; kind: 'normal' | 'exception' }>;
  exceptionRoutes: Array<{ codes: string[]; count: number }>;
  deviations: Array<{ code: string; count: number }>;
  initialCode?: string;
  finalCode?: string;
}
```

**Что делать:**
- Добавляй узлы в порядке первого появления.
- Добавляй переход `from → to` только один раз для каждой пары и типа перехода.
- Передавай одну модель в оба генератора.
- Строй формулу по подтверждённому связному основному маршруту из обычных переходов.
- Передавай в DOT все уникальные переходы модели, включая исключающие.

**Запрещено:**
- Повторно добавлять переходы завершающего маршрута в DOT.
- Создавать отдельный набор переходов только для диаграммы.

---

## normativeorder.H3.2 Не создавай переходы при очистке фактической последовательности
Нормализация может убрать шум из представления, но не может добавлять связи, которых нет в фактическом журнале.
**Почему важно:** удаление промежуточного события не доказывает прямой переход между его соседями.

---

## normativeorder.H4.2 Обрабатывай прямые повторы и события `E*` отдельно
Применяй следующие правила к исходной последовательности:

| Ситуация | Действие |
|---|---|
| `X → X` | Не добавляй self-loop в нормативный граф; зафиксируй повтор как отклонение. |
| `X → E* → Y` | Добавь только исключающие переходы `X → E*` и `E* → Y`; не добавляй `X → Y` только на основании этой ветви. |
| Несколько подряд `E*` | Сохрани всю ветвь от входного обычного события до выходного обычного события. |

**Запрещено:**
- Удалять `E*` фильтрацией, которая без проверки подтверждённой обычной связи соединяет предыдущее и следующее обычные события.
- Включать `E*` в основной нормативный порядок.

---

## normativeorder.H3.3 Используй однозначный язык записи порядка
Каждое выражение должно иметь единственное структурное чтение по правилам приоритета и скобкам.
**Почему важно:** текстовый порядок должен соответствовать одному и тому же автомату для человека и генератора диаграммы.

---

## normativeorder.H4.3 Формируй выражение из структурированной модели и печатай его по грамматике
Сначала построй AST или эквивалентное дерево маршрутов, затем сериализуй его. Не собирай формулу конкатенацией строк из отдельных независимых маршрутов.

```text
Path       := Term (" → " Term)*
Term       := Code | Optional | Repeat | Choice
Optional   := "(" Path ")?"
Repeat     := "(" Path ")⁺"
Choice     := "(" Path (" | " Path)+ ")"
```

**Что делать:**
- Используй `→` только для обязательного перехода.
- Используй `|` только для альтернативных исходящих ветвей одного узла.
- Используй `?` только для ветви, допускающей ноль или одно прохождение.
- Используй `⁺` только для подтвержденного цикла.
- Заключай в скобки каждую альтернативу, необязательный и повторяемый фрагмент.

---

## normativeorder.H3.4 Выделяй циклы и ветви по структуре графа
Цикл и развилка определяются переходами графа, а не количеством совпадений подстрок в журнале.
**Почему важно:** повторение кода в разных местах не всегда означает общий цикл.

---

## normativeorder.H4.4 Выбирай цикл и точку возврата детерминированно
Используй strongly connected components (SCC) обычных переходов.

**Что делать:**
- Помечай компонент как цикл, если он содержит не менее двух узлов или подтвержденный self-loop, не являющийся шумом.
- Выбирай точку возврата как узел цикла с самым ранним появлением в фактической последовательности.
- Отображай все исходящие ветви точки возврата через `|`.
- Факторизуй общий префикс и суффикс ветвей только если это не добавляет новых путей.

**Запрещено:**
- Помещать в `(...)⁺` маршруты, не возвращающиеся в выбранную точку возврата.
- Делать обязательной ветвь, которая наблюдалась лишь как альтернатива.

---

## normativeorder.H3.5 Показывай исключения вне основного порядка
События `E*` являются ветвями отклонений и не меняют семантику основного пути.
**Почему важно:** основной нормативный порядок должен оставаться читаемым и не превращать редкие ошибки в штатные шаги.

---

## normativeorder.H4.5 Печатай исключающие ветви отдельной строкой
После основного выражения выводи все уникальные ветви отклонений в формате:

```text
Ветви отклонений: A1 → E1 → A2; B → E2 → B1
```

В DOT отображай узлы `E*` красным цветом, а инцидентные переходы — красной пунктирной линией. Следуй `diagramsmanifest.md` при хранении и рендеринге документационных диаграмм.

---

## normativeorder.H3.6 Проверяй эквивалентность перед выдачей результата
Формула, граф и фактическая последовательность должны быть проверяемо согласованы.
**Почему важно:** визуально аккуратная диаграмма не компенсирует ошибочный порядок.

---

## normativeorder.H4.6 Проверяй модель автоматическими тестами
Для каждого изменения распознавания добавь тесты, которые подтверждают:

- все переходы фактической последовательности, кроме self-loop-повторов, присутствуют в модели с правильным типом;
- self-loop-повторы присутствуют в отчёте отклонений;
- в модели нет переходов, которых не было в фактах;
- `E*` не создает прямой обычный переход между соседями;
- DOT содержит каждое уникальное ребро ровно один раз;
- AST формулы использует только подтверждённые обычные переходы из той же модели, что и диаграмма;
- формула не обязана повторять в линейном виде все альтернативные рёбра DOT, если они выведены отдельными ветвями;
- необязательная ветвь отображается как оба допустимых пути в графе.

**Запрещено:**
- Считать формулу корректной только потому, что PNG успешно сформирован.
- Исправлять расхождение текста и диаграммы изменением только одного из представлений.
