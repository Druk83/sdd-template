# Построй граф нормативного порядка событий (H6)

Процедура применяется внутри этапа [5.2] только по явному запросу разработчика.
Она описывает конечный автомат нормативной последовательности и не заменяет
BPMN-карту бизнес-процесса.

> **Манифесты:** перед началом прочитай `.manifest/normativeordermanifest.md` и
> `.manifest/diagramsmanifest.md`. Правила манифестов имеют приоритет над этим
> кратким порядком действий.

---

## Условия запуска

Запускай процедуру только если одновременно выполнены условия:

- разработчик явно запросил граф нормативного порядка или конечный автомат;
- есть подтверждённая фактическая последовательность событий из журнала,
  требований или другого источника проекта;
- понятны начальный и конечный узлы либо эти сведения зафиксированы как GAP.

Если фактической последовательности нет, не восстанавливай переходы по
предположению. Зафиксируй GAP и не создавай граф.

## Входы

- `docs/requirements/сценарии/<domain_slug>/карта процесса.md`;
- `docs/requirements/сценарии/<domain_slug>/каталог мероприятий.md`;
- подтверждённая фактическая последовательность событий;
- решения и ограничения разработчика по области анализа.

## Выходы

- раздел «Нормативный порядок событий» в карте процесса;
- каноническая модель переходов, использованная для формулы и графа;
- `docs/requirements/сценарии/<domain_slug>/diagrams/<process>-normative-order.dot`;
- PNG или SVG рядом с DOT-файлом после рендеринга через `.tools/plantuml-render/`;
- ссылка на изображение из карты процесса с комментарием на исходный DOT.

## Порядок выполнения

1. Выпиши из фактической последовательности уникальные узлы и переходы.
2. Сформируй одну `NormativeOrderModel` согласно
   `.manifest/normativeordermanifest.md`.
3. Отдели обычные переходы от исключений, повторов и подтверждённых циклов.
4. Построй текстовую формулу из модели, а не конкатенацией независимых ветвей.
5. Построй DOT из той же модели. Не добавляй в DOT переходы, которых нет в фактах.
6. Отрази исключения отдельными ветвями и сохрани обозначение событий `E*` по
   правилам нормативного манифеста.
7. Сохрани DOT в каталоге диаграмм и выполни рендеринг:

   ```powershell
   .tools\plantuml-render\plantuml-render.bat `
     --diagram-type graphviz `
     --path 'docs\requirements\сценарии\<domain_slug>\diagrams\<process>-normative-order.dot'
   ```

8. Проверь, что формула, DOT и фактическая последовательность эквивалентны.
   Успешное создание PNG само по себе не подтверждает корректность модели.
9. Добавь ссылку на PNG в карту процесса и укажи путь к исходному DOT.

## Что запрещено

- запускать процедуру без явного запроса разработчика;
- использовать конечный автомат вместо BPMN для описания ролей, задач и обмена
  сообщениями бизнес-процесса;
- добавлять переходы на основании только соседства событий после очистки журнала;
- смешивать нормативный маршрут и исключения в одну неразличимую формулу;
- строить формулу и DOT из разных наборов данных;
- сохранять только PNG без исходного DOT.

## Критерии готовности

- [ ] Запрос разработчика и источник фактической последовательности зафиксированы.
- [ ] Все узлы и переходы DOT подтверждены источниками.
- [ ] Формула и DOT построены из одной модели.
- [ ] Повторы, циклы и исключения обработаны по нормативному манифесту.
- [ ] DOT отрендерен через `.tools/plantuml-render/`.
- [ ] PNG/SVG отображается корректно и связан с картой процесса.
- [ ] GAP заполнен, если фактов для перехода недостаточно.
