# `.diagrams/`

Содержание синхронизируется с версией Framework, указанной в корневом `README.md`.

Каталог содержит эталонные исходники диаграмм, которые объясняют процесс SDD и
используются для синхронизации `.requirements/трек разработки.md`,
`.manifest/sddmanifest.md` и процедур Framework. Это не каталог диаграмм
прикладного проекта: прикладные диаграммы создаются в `docs/requirements/`.

## Канонические диаграммы процесса

Для каждой канонической диаграммы процесса в каталоге хранится исходник
(`.plantuml` или `.bpmn`) и соответствующий рендер `.png`:

- `SDD-Development-Process.bpmn` и `SDD-Development-Process.png` — общий поток
  этапов SDD;
- `SDD-Sequence-01`–`SDD-Sequence-16` — последовательности основных этапов;
- `SDD-Sequence-10a-Stage5a-UI.plantuml` — последовательность условного
  подэтапа `[5.a]` планирования UI и пула экранов.

Исходники последовательностей показывают четыре фазы выполнения: инициализацию,
заполнение базового контекста, уточнение и финализацию с подтверждением
разработчика. Условные ветви (`GAP`, `not_applicable`, выбор профиля и
`[5.a]`) являются частью поведения, а не декоративными примечаниями.

## Эталонные исходники, поставляемые Framework

Следующие файлы являются эталонными (reference) источниками и включаются в выпуск
(release) по контракту `.tools/sdd-template-release/build_release.py`:

- `последовательность событий.plantuml` — объединённая каноническая
  последовательность; в ней отражены выбор профиля требований на `[3]` и
  условный `[5.a]` перед `[6]`;
- `example AL.plantuml`, `example BL.plantuml`, `example TL.plantuml` —
  эталонные примеры диаграмм ArchiMate.

Эти эталонные источники не являются результатами конкретного проекта. Рендеры
для них могут создаваться локально при проверке, но наличие PNG рядом с каждым
поставляемым исходником не является условием контракта выпуска (release).

Файл `3.plantuml`, если он присутствует локально, не относится к каноническому
набору выпуска (release) и игнорируется Git как устаревший локальный артефакт.
Не следует
использовать его как источник актуальной процедуры.

## Проверка и рендеринг

Рендеринг выполняется штатным инструментом `.tools/plantuml-render/` после
запуска доступного Kroki-сервиса. Для проверки исходников без генерации файлов:

```powershell
.tools/plantuml-render/plantuml-render --dry-run --path .diagrams/
```

Для диаграмм, являющихся результатами документации, обязательны исходник и
рендер рядом с ним согласно `.manifest/diagramsmanifest.md`. Для reference-
источников действует отдельное правило выше.

## Связанные правила

- `.manifest/diagramsmanifest.md` — политика диаграмм и правила рендеринга;
- `.manifest/sddmanifest.md` — порядок работы агента по этапам SDD;
- `.requirements/трек разработки.md` — последовательность этапов и выходные
  артефакты;
- `/README.md` — обзор Framework и навигация.
поставляемым исходником не является условием контракта выпуска (release).
